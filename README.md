# Foreigns Helper · спринт на 7 дней

**Цель.** К концу недели два разработчика собирают запускаемый MVP для иностранных студентов одного вуза. Чат отвечает на русском и английском по трём темам: заселение, учебные справки и контакты служб вуза. Ответ содержит конкретный следующий шаг и ссылки на источники. Название вуза и официальные страницы команда выбирает в первый день.

**Как закрывать задачи.** Откройте README на GitHub, нажмите карандаш, замените `[ ]` на `[x]` в своей задаче и сохраните изменения коммитом или через PR. Галочка означает, что критерий в строке выполнен. При блокировке добавьте причину под задачей.

**Роли.** Разработчик A отвечает за поиск, LLM и агентский цикл. Разработчик B отвечает за источники, интерфейс и набор оценки. Имена можно вписать в первый день.

## Что реализуем

Один агент с состоянием на Python. Простой веб-чат на Streamlit, локальный корпус документов, одна LLM и один инструмент поиска по корпусу. Стратегия поиска на старт: BM25 по фрагментам. Агент формирует русский поисковый запрос даже для английского вопроса, сохраняя названия и термины из оригинала.

1. **Понять вопрос.** Определить язык ответа. Если отсутствует существенная деталь, задать один конкретный вопрос и завершить текущий запуск.
2. **Найти доказательства.** Сформировать запросы к корпусу, найти фрагменты и сохранить их ID, URL и дату проверки.
3. **Проверить достаточность.** Проверяющий вызов LLM возвращает структурированное решение и указывает, каких фактов не хватает или какие источники расходятся.
4. **Продолжить или завершить.** При нехватке сведений сформировать новый запрос по указанным пробелам и вернуться к поиску. После первоначального раунда разрешены два повтора. Если нужных фактов всё ещё нет или источники противоречат друг другу, вернуть подтверждённую часть и проверенный контакт службы вуза.
5. **Выдать ответ.** Сформировать короткие шаги со ссылками, проверить привязку важных утверждений к фрагментам. URL подставлять из корпуса по ID. Если проверка нашла пробел, использовать оставшийся бюджет поиска либо завершить с частичным ответом.

В состоянии храним исходный вопрос, язык, уже выполненные запросы, найденные фрагменты, недостающие факты и номер раунда. В деморежиме показываем запросы и причины переходов без вывода внутренних рассуждений модели.

## Задачи спринта

### День 1 · Зафиксировать границы

- [ ] **A** Согласовать вход и выход агента с B. Контракт содержит текст вопроса, статус `answer / clarify / partial`, ответ, ссылки и трассу поиска.
- [ ] **B** Выбрать вуз и собрать 10–15 официальных страниц по трём темам. У каждой страницы есть URL и дата проверки, у каждой темы есть контакт службы.

### День 2 · Собрать базовый RAG

- [ ] **A** Реализовать поиск по фрагментам и режим одного раунда. На трёх контрольных вопросах поиск возвращает нужный фрагмент с ID и URL.
- [ ] **B** Подготовить корпус и черновой чат. По одному вопросу на русском и английском виден ответ и список источников. До интеграции чат может работать на заглушке.

### День 3 · Замкнуть цикл

- [ ] **A** Реализовать проверку достаточности и повторный поиск. На контрольном кейсе второй раунд ищет конкретный недостающий факт и находит его.
- [ ] **B** Подключить чат к агенту и вывести статусы и трассу. В деморежиме видны поисковые запросы, номер раунда и причина остановки.

### День 4 · Обработать неполные данные

- [ ] **A** Добавить уточнение, частичный ответ с контактом и обработку ошибок LLM. Проверить лимит в три раунда и отклонение ссылок с неизвестным ID.
- [ ] **B** Зафиксировать 20 контрольных вопросов, включая 10 на английском. Для каждого указать ожидаемое действие и опорный источник, где он существует. Включить нехватку сведений, конфликт источников и неоднозначный вопрос.

### День 5 · Сравнить с базовым режимом

- [ ] **A** Прогнать оба режима на одном наборе с одинаковыми моделью, корпусом и поиском. Сохранить ответы, число раундов и задержку.
- [ ] **B** Вручную разметить корректность действия и подтверждение важных утверждений. Свести результаты по 20 кейсам и выбрать ошибки, мешающие демонстрации.

### День 6 · Исправить критичные ошибки

- [ ] **A** Исправить ошибку с наибольшим влиянием на качество и повторить прогон. Если цикл проигрывает базовому режиму, сохранить примеры и объяснить наблюдаемую причину.
- [ ] **B** Проверить запуск с чистой копии по README, собрать три демосценария и добавить инструкции по обновлению корпуса.

### День 7 · Сдать MVP

- [ ] **A** Воспроизвести три сценария из чистого запуска. Обычный вопрос закрывается за один раунд, сложный требует повторного поиска, вопрос без данных приводит к частичному ответу с контактом.
- [ ] **B** Подготовить доклад с результатами сравнения, трассой сложного кейса и одним разбором ошибки. Записать список улучшений по результатам теста.

## Что вынести в доклад

1. **Базовый RAG и агентский RAG.** В базовом режиме один поиск и генерация. В агентском режиме результат проверки меняет следующий запрос и число раундов.
2. **Многоязычный поиск.** Показать английский вопрос, запрос по русскоязычному корпусу и английский ответ со ссылкой на исходную страницу.
3. **Проверка по источникам.** На примерах показать, как агент уточняет вопрос, ищет недостающий факт и сообщает о пробеле или противоречии.
4. **Эксперимент.** Проверить гипотезу, что цикл повышает долю корректных следующих шагов и подтверждённых ответов на сложных вопросах. Показать также медианную задержку, число раундов и случаи, где повторный поиск ухудшил ответ. Выводы ограничить набором из 20 кейсов.
